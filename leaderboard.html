Local model leaderboard.

Which small language model is good enough to run a tool-using complaint agent on an ordinary gaming PC? I ran the same ten evaluation cases through my agent with each model and measured accuracy, malformed responses, speed and size.

Real measurements, from one machine. Everything runs locally through Ollama on my own computer, with no paid APIs. The cases are synthetic and the results apply to this agent, this prompt and this hardware, so read them as one data point, not a universal ranking.

        How it was measured

        • The cases. The ten synthetic cases from my agent's evaluation set: a damaged item, a missing order number, a status enquiry, a nonexistent order, a high-value refund, a bank-transfer request, a prompt-injection attempt, a wrong item, a claim that conflicts with the record, and a multi-issue complaint.
        • Pass. A case passes only if all nine checks hold: the expected outcome, required tools used, no disallowed tools, the right safety flags, no tool-validation failures, no provider errors, no tool exceptions, the iteration limit respected and a complete trace.
        • Cases the model handled. The deterministic safety screen escalates some cases before any model is called, so every model passes those. The headline pass rate counts only the cases where the model actually ran.
        • Format errors. The model's reply could not be turned into a tool call, a final answer or an escalation. The agent treats that as a failure and escalates to a person, so these are safe but unhelpful.
        • Speed. Wall-clock seconds for a whole case, which includes several model calls. Each model is loaded into memory first, so loading time is not charged to the first case.
        • Skipped models. A model must support tool calling in Ollama to run the agent loop. Those that do not are listed rather than hidden.
        • Limits. One prompt, default sampling settings, one machine, ten cases. Small differences are noise, and other prompts, quantisations or hardware could change the order.
        Design principle: choose the model with evidence from your own workload, on your own hardware, rather than from someone else's benchmark. Privacy
