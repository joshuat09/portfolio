AI SAFETY · INTERACTIVE LAB

Prompt-injection lab.

Can you trick an AI customer-complaints agent into paying out money, leaking another customer's data or revealing its instructions? Write an attack, then switch its defences on and off to see which layer actually stops it.

  1. Your message

A simulation, not a real model. The agent here is a scripted stand-in that is deliberately gullible, the way a weak model can be. Three of the defences are ported from my real complaint agent; three are added for this page and labelled. It teaches the idea of layered defence. It is not a security audit.

What happened, step by step

    Which layer stops which attack?

    Each cell shows whether that layer, switched on on its own, stops the attack. Notice that no single layer covers everything, and that the phrase filter only catches the attacks written the classic way. Select a row to load that attack.

    What this shows

    • Filtering words is not enough. The phrase filter stops "ignore previous instructions" but not the same request obfuscated, translated or hidden in a pasted note, because a flexible model understands all of them.
    • The strongest defences are structural. My agent cannot issue a refund because it has no such tool, and it cannot be talked into one. That works whatever the model is persuaded to say.
    • Some attacks use permitted tools. Looking up someone else's order uses a normal read-only tool, so the tool list cannot help; an ownership check does.
    • Every block ends in a person. A stopped message is escalated for human review rather than silently dropped.
    • Limits. The stand-in follows simple patterns. A real language model is fuzzier, so a real attacker may find routes this one does not, which is why layers matter more than any single rule.
    Design principle: assume the model will sometimes be fooled, and make sure being fooled cannot cause harm.Privacy
